# 文档风险审查知识库 · 总纲

> **本知识库的用途**：作为其他大模型进行「文档风险审查」时的参考资料库（RAG 知识源 / 上下文注入）。
> 覆盖文档类型：合同/协议、内部制度、对外公告、招投标文件。
> 覆盖风险维度：合规风险、法律风险、数据安全风险、资金风险。
>
> **生成方式**：材料来自中国人大网、国务院各部委官网、交易所、司法机关等官方渠道，原文存档于 `../sources/`。
> **免责声明**：本库为技术参考资料，不构成法律意见。所有法条引用与案例均标注来源，标记「待核实」的内容使用前必须回查原文。

## 〇、⚠️ 本库可信度实况（务必先读）

本库在装配阶段做了一次独立核验，结果如下。**这些数字本身就是知识库的一部分**——它决定了下游模型该以多大信心使用本库。

### 0.1 法规引用的原文存档率

| 维度文件 | 引用法规/文件 | 有本地原文存档 | 存档率 | 文内「待核实」标记 |
|----------|--------------|---------------|--------|-------------------|
| 01 合规风险 | 44 | 10 | 23% | 21 处 |
| 02 法律风险 | 33 | 4 | 12% | 24 处 |
| 03 数据安全风险 | 22 | 7 | 32% | 8 处 |
| 04 资金风险 | 28 | 4 | 14% | 22 处 |
| **合计（去重前）** | **127** | **25** | **约 20%** | **75 处** |

**这意味着**：本库约 80% 的法条引用是采集时在线阅读后转述的，**没有留存原文可供离线逐字核对**。条款号大概率正确（均来自官方页面），但**不能排除转述误差**。

### 0.2 案例的可核实性分布

| 等级 | 数量 | 说明 |
|------|------|------|
| A · 可直接引用 | **1** | 主体与文号齐全，可回官方渠道核对 |
| B · 引用需附提示 | **10** | 主体或文号其一可查，或属公开重大事件 |
| C · 仅作模式参考 | **28** | 主体脱敏且无可定位文号，**不得作为依据** |

**这意味着**：本库 39 个案例中，只有 1 个可以无保留地当作判例依据引用。若下游模型被要求"给出判例支持"，绝大多数情况下应如实回答"本库无可直接引用的判例"。

### 0.3 已知必须回查的高风险项

1. **《反不正当竞争法》** —— 本次采集到的是 **1993 年版本**，非现行有效版本。本库中该法相关条款号**存疑**，引用前必须核实现行版本。
2. **《民法典》全文未能获取** —— 本库大量引用民法典条款号（496-498、506、577-585、586-588 等），均未经原文核验。这些是最常被引用的条款，**建议优先补齐原文**。
3. **国家标准（GB/T 35273 等）** —— 需付费获取，本次未取得，相关表述来自二手资料。

### 0.4 已在装配阶段修正的错误

| 问题 | 处理 |
|------|------|
| 统一社会信用代码正则长度错误（19 位）+ 前缀语义错误（误用省级行政区划码） | 已修正为 18 位全字符集 + GB 32100-2015 校验算法，并实测通过 |
| 15 份合同示范文本扩展名标为 `.pdf`，实为 `.doc`/`.docx` | 已按文件头魔数实测类型统一修正 |
| 案例分级过宽（把"最高人民法院指导性案例"这类**类别标签**当作案号） | 已收紧判定：必须匹配真实案号形态，11 个案例相应降级 |
| 资金风险案例地名错误（鹤壁市 / 鹤山市） | 已核实修正为鹤山市 |

> **给下游模型的总纪律**：使用本库时，**可信度标记必须随内容一起传递给最终用户**。把 ⚠️ 或 ❓ 级别的内容当作确定事实输出，比不使用本库更有害。

### 0.5 机器可识别信号的实测结果（这部分可放心使用）

与法条引用的低存档率相反，本库的**扫描规则经过实测验证，质量可靠**：

| 检验项 | 结果 |
|--------|------|
| 提取正则总数 | **102 条** |
| 可编译（Python `re`） | **102 / 102** ✅ |
| 高危条款正例覆盖 | **10 / 10** ✅（最终解释权、概不退换、单方变更、免责、日 0.5% 滞纳金、风险转嫁、限定转售价、强制搭售、管辖偏袒等） |
| 无辜文本误报 | **0 次** ✅（对"解释权由双方协商""七日无理由退换""按 LPR 计息""被告住所地管辖"等合规表述均未误报） |

## 二、风险分级标准（全库统一）

审查结论必须使用这套分级，不得自创等级。

| 等级 | 代码 | 判定标准 | 处置要求 |
|------|------|----------|----------|
| **高危** | `HIGH` | 满足任一：① 违反法律/行政法规的强制性规定，条款无效或合同无效；② 可能触发行政处罚、刑事责任；③ 造成己方重大不可控损失（无责任上限、无限连带）；④ 敏感个人信息明文泄露；⑤ 资金条款超法定上限或存在明确资金流失通道 | 必须修改，不改不签 |
| **中危** | `MEDIUM` | 满足任一：① 违反部门规章、行业规范、监管指引；② 权利义务边界模糊，争议时己方举证不利；③ 条款不对等但未到无效程度；④ 一般个人信息处理缺少合规基础；⑤ 付款条件叠加导致回款周期显著延长 | 建议修改，需业务与法务共同评估后决策 |
| **低危** | `LOW` | 满足任一：① 表述不规范、术语不统一、引用文号错误；② 缺少最佳实践条款但不影响效力；③ 格式、排版、附件编号问题 | 提示优化，可接受 |
| **提示** | `INFO` | 非风险，但需要人工确认的事实性事项（如"本条引用的标准已废止，请确认是否改用新版"） | 记录并提请确认 |

**升级规则**：
- 同一条款同时命中 ≥2 个维度的中危 → 升为高危。
- 涉及金额 ≥ 合同总额 30% 的中危资金条款 → 升为高危。
- 相对方为政府机关、国有企业、金融机构时，合规风险等级整体上浮一级。

## 三、审查工作流（建议模型遵循的顺序）

```
第0步：文档定性
  └─ 判断文档类型（合同/制度/公告/招投标）→ 决定重点审查哪几章，参见下方「六、按文档类型的审查侧重」
  └─ 判断行业属性（金融/医疗/建工/互联网/政府采购）→ 决定叠加哪些特殊监管要求
  └─ 判断相对方性质（个人/民企/国企/政府/境外）→ 决定合规基线

第1步：结构性检查（缺什么）
  └─ 对照该文档类型的「必备条款清单」，列出缺失项
  └─ 缺失即为风险，通常 MEDIUM 起步，核心条款缺失为 HIGH

第2步：机器信号扫描（快筛）
  └─ 跑四份风险文件中的「机器可识别信号」正则/关键词
  └─ 跑 03 的 PII 字段识别规则表
  └─ 跑 04 的数值校验规则（大小写一致、单价×数量、比例超限）
  └─ 输出候选风险点清单（此步只做召回，允许误报）

第3步：逐条语义研判（精判）
  └─ 对每个候选点，回查对应风险文件的「条款风险清单」
  └─ 确认法律依据 → 确认风险等级 → 生成改写建议
  └─ 排除误报（如"最终解释权"出现在引用他人条款的批判性描述中）

第4步：全文补充通读
  └─ 正则扫不到的语义风险：责任分配失衡、条件互相矛盾、前后条款冲突、定义与正文不一致

第5步：出具结论
  └─ 按下方输出规范组织
```

## 四、输出规范（供下游模型直接采用）

### 4.1 单条风险的标准结构

```json
{
  "id": "R-001",
  "dimension": "资金风险",
  "sub_category": "付款条件-背靠背条款",
  "level": "HIGH",
  "location": {"clause_no": "第7.2条", "page": 5, "quote": "原文摘录，不超过200字"},
  "finding": "一句话说清问题是什么",
  "why_risky": "法律后果推演：会导致什么",
  "basis": [
    {"law": "《保障中小企业款项支付条例》", "article": "第九条", "url": "https://..."}
  ],
  "suggestion": "可直接替换的改写文本",
  "confidence": "高|中|低",
  "reference_case": "案例编号或案号"
}
```

### 4.2 报告组织顺序

1. **风险总览**：高/中/低各几条，一句话总体结论（建议签署 / 修改后签署 / 不建议签署）
2. **高危项**：逐条展开，含原文引用 + 依据 + 改写建议
3. **中危项**：逐条展开，可适当精简
4. **低危与提示项**：列表形式
5. **缺失条款清单**：应有而未有的条款
6. **依据索引**：本次引用的全部法条与案例

### 4.3 表述纪律（重要，防止模型幻觉）

- **必须引用原文**：指出风险时，一律先摘录被质疑的条款原文，再作判断。不得凭印象转述。
- **法条必须精确到条**：写「《民法典》第五百八十五条」，不写「《民法典》相关规定」。凡不能确定条款号的，写「依据待核实」并降低 confidence。
- **不得编造**：案号、罚单文号、处罚金额、法条内容，一律不得推测生成。本库中标注「待核实」的内容，引用时必须同步传递该标注。
- **区分"违法"与"不利"**：只有违反强制性规定才能称"无效/违法"；仅对己方不利的条款应表述为"商业上不利，建议争取修改"。
- **给出可执行建议**：改写建议要写成可以直接粘贴进合同的完整句子，不写"建议明确约定"这类空话。

## 五、四大风险维度速览

| 维度 | 一句话定义 | 核心问法 | 主要法律锚点 |
|------|-----------|----------|-------------|
| **合规风险** | 条款内容本身违反法律法规或监管规则 | "这么写，监管会不会罚我？" | 民法典496-498、消保法、反垄断法、反不正当竞争法、招标投标法、政府采购法、广告法、证券法、劳动合同法 |
| **法律风险** | 权利义务约定不清或惩罚机制失衡，导致争议时处于不利地位 | "打官司我会不会输、会不会赔多？" | 民法典合同编（尤其506、577-585、586-587）、合同编通则司法解释 |
| **数据安全风险** | 个人信息/重要数据的处理缺乏合法基础，或文档本身泄露 PII | "这里面有没有不该出现的个人信息？数据条款合不合规？" | 个人信息保护法、数据安全法、网络安全法、GB/T 35273、数据出境相关办法 |
| **资金风险** | 金额存在错误/异常，或付款条件导致资金损失、回款失控 | "钱数对不对？什么时候能收到钱？钱会不会打错地方？" | 招标投标法实施条例（保证金上限）、保障中小企业款项支付条例、企业内部控制规范、支付结算办法 |

## 六、按文档类型的审查侧重

不同文档类型的风险分布差异很大。先定性，再决定把精力放在哪几章。

| 文档类型 | 必看的核心条款 | 风险高发位置 | 该类型的典型高危表述 |
|----------|---------------|-------------|---------------------|
| **合同 / 协议** | 主体与授权、标的与验收、价款与付款、违约责任、知识产权、保密与数据、争议解决 | **付款条款**（资金）、**违约与免责条款**（法律）、**格式条款**（合规）、**个人信息条款**（数据） | "最终解释权""概不退换""待业主付款后支付""一切后果由乙方承担" |
| **内部制度** | 制定依据与适用范围、职责分工与不相容岗位分离、审批权限矩阵、违规问责、生效与解释权 | **审批权限与授权额度**（资金）、**与上位法冲突**（合规）、**数据分类分级与权限**（数据） | "员工自愿放弃社保""解释权归人力资源部""特殊情况可由总经理直接审批" |
| **对外公告** | 披露事项完整性、金额与比例、关联关系说明、风险提示、董事会审议程序 | **信息披露完整性**（合规）、**金额与预案数据一致性**（资金）、**联系人 PII 泄露**（数据） | 遗漏关联关系、金额与前期公告不一致、公告中直接列出联系人手机号与身份证 |
| **招投标文件** | 资格条件、评标办法、保证金、合同条款附件、废标条款、付款方式 | **资格条件排他性**（合规）、**保证金比例**（资金）、**评委与投标人 PII**（数据）、**中标后合同条款**（法律） | "须具备本地纳税证明""投标保证金为估算价 5%""要求提供法定代表人身份证复印件" |

**审查优先级**：合同 → 先付款与违约；制度 → 先权限与上位法冲突；公告 → 先完整性与数据一致性；招投标 → 先资格条件与保证金比例。

> 说明：本节为压缩版。原计划的独立文档类型速查文件（含四类文档标准结构骨架与完整交叉矩阵）**未纳入本次交付**。

## 七、跨维度联动检查点

有些问题单看一个维度发现不了，必须交叉验证：

| 联动场景 | 检查方法 | 风险 |
|----------|----------|------|
| 收款账户 vs 签约主体 | 比对合同落款主体名称与付款条款中的账户户名是否**完全一致** | 不一致 = HIGH，典型合同诈骗/资金挪用手法 |
| 合同金额 vs 招标公告金额 | 比对中标金额与合同金额偏差 | 偏差 >10% 且无书面变更 = HIGH，违反招标投标法第46条 |
| 保密条款 vs 数据条款 | 有保密义务但无数据处理协议 | 涉及个人信息时 = HIGH，个保法第21条 |
| 违约金 vs 合同总额 | 违约金累计上限是否超过合同总额 | 无上限或超100% = MEDIUM~HIGH |
| 公告披露内容 vs 合同保密条款 | 需公告的重大合同却约定全文保密 | 上市公司 = HIGH，信披违规 |
| 个人信息条款 vs 跨境条款 | 有境外接收方但无出境合法性基础 | HIGH，个保法第38条 |
| 制度文本 vs 上位法 | 内部制度授权范围超出法律允许 | 如"员工放弃社保"= HIGH，条款无效 |

## 八、使用本库时的已知边界

1. **时效性**：法律法规会修订。本库标注了各文件的采集日期，**引用前应确认所依据的法条是否为现行有效版本**。特别注意近年频繁修订的：反不正当竞争法、公司法、招标投标法配套规则、数据跨境规定。
2. **地域范围**：以中国内地法律为主。涉及港澳台、境外交易的，本库仅在数据安全维度提供 GDPR 参照，其余需另行检索。
3. **行业特殊性**：金融、医疗、教育、建工、军工等行业有大量专属监管要求，本库只覆盖通用部分与部分金融要求，行业深度审查需叠加专门规则。
4. **不替代人工**：高危结论、金额重大的交易、涉刑风险，必须由法务/合规人员复核。
