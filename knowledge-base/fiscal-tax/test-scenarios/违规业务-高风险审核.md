# 违规业务高风险审核测试用例（5 个剧本）

> **用途**：验证 EAIDE 审核专家系统在**明显违规**业务场景下，期望触发**拦截 + 升级审批 + SHA-256 链式审计**。
>
> **预期结果**：`score < 30`、合规规则多个 `violation` 或 `critical` 命中、`needs_hitl=True`、触发**双人复核**（V1）或**总经理审批**。

---

## 场景 V1 · 关联方虚开专票抵扣

### 业务背景
- 公司：可F能源公司
- 申请人：财务总监（ID：`cfo-011`）
- 业务类型：**取得虚开专票抵扣**
- 金额：上游公司"**XX 实业**"开具增值税专用发票 **¥5,000,000** + 增值税 **¥650,000**（13%）
- 对方公司：XX 实业有限公司（**已被税务部门认定为走逃户**）

### 凭证材料（**部分虚假**）

| 编号 | 类型 | 问题 |
|---|---|---|
| E01 | 增值税专用发票 | ❌ 上游公司已失信走逃 |
| E02 | 合同 | ❌ 合同签订日期早于对方公司注册日 |
| E03 | 入库单 | ⚠ 无法对应实物 |
| E04 | 银行付款回单 | ⚠ 资金回流至个人账户 |
| E05 | 验收单 | ❌ 缺有效签字 |

### 自动识别要素

| ID | 触发 | 来源 | 风险等级 |
|---|---|---|---|
| V-LAW-005 | 上游公司为失信 / 走逃户 | 公告 | **critical** |
| V-LAW-013 | 资金回流（疑似资金回流） | 刑法 205 | **critical** |
| V-LAW-007 | 三流不一致（货物流缺失 / 资金回流） | 刑法 205 | **critical** |
| V-LAW-001 | 品名与实际经营业务不符 | 发票办法 | **violation** |

### 法规点
- 刑法 205 条（虚开增值税专用发票罪）
- 增值税法第 8 条
- 发票办法

### 决策流程

```
命中 critical 风险
   ↓
needs_hitl=True（强制人工复核）
   ↓
升级到 V1 dual-first 双人复核审批
   ↓
触发 SHA-256 签名链审计
   ↓
建议移送公安机关（critical 自动建议）
```

### 期望结果

### 测试断言

## 场景 V2 · 高管个税偷税

### 业务背景
- 公司：可G网络游戏公司
- 申请人：CEO（ID：`ceo-012`）
- 业务类型：**现金发放高管奖金，不代扣个税**
- 金额：向 8 名高管发放 **2023 年度奖金** 合计 **¥12,000,000**（未代扣个税）
- 个税应扣：约 **¥3,500,000**

### 自动识别要素

| ID | 触发 | 风险 |
|---|---|---|
| I-LAW-001 | 工资薪金未扣缴个税 | **violation** |
| T-LAW-014 | 个税代扣未申报 | **violation** |
| C-LAW-008 | 偷税数额 ≥ 100 万 + 占应纳税额 30% 以上 | **critical**（重大违法） |

### 法规点
- 个税法第 24 条（扣缴义务）
- 征管法第 63 条（偷税）
- 刑法 201 条（逃税罪）

### 决策流程

```
命中偷税 100 万以上 + 占应纳税额 30% 以上

```

## 场景 V3 · 财务会计制度未备案 + 跨年汇算清缴延期

### 业务背景
- 公司：可H贸易公司（**小规模纳税人**）
- 申请人：财务助理（ID：`fa-013`）
- 业务类型：所得税汇算清缴 **逾期未办**
- 应当申报日期：**2024-05-31**
- 实际申报日期：**2024-09-15**（**逾期 107 天**）
- 应纳税所得额：**¥1,200,000**（小微企业，5% 税率）

### 自动识别要素

| ID | 触发 | 风险 |
|---|---|---|
| P-LAW-001 | 财务会计制度自领取税务登记 15 日内未备案 | warning |
| T-LAW-002 | 年度终了 5 个月内未汇算清缴（**逾期 107 天**） | **violation** |
| I-LAW-001（关联） | 应纳税额缓缴 → 加收滞纳金（年化 18.25% × 107 天） | warning |

### 法规点
- 实施细则第 17 条（财务制度备案）
- 所得税法第 49 条（汇算清缴期限）

### 决策流程

```
命中 T-LAW-002 汇算清缴逾期
   ↓
needs_hitl=True
   ↓
系统自动建议：补申报 + 加收滞纳金（107 天 × 万分之五）+ 接受行政处罚
   ↓
升级到财务总监 + 税务主管 双签
```

## 场景 V4 · 关联方转让定价独立交易偏离

### 业务背景
- 公司：可I跨国IT咨询公司（**外商投资企业**）
- 申请人：税务总监（ID：`tax-014`）
- 业务类型：**支付境外母公司"管理咨询费"**
- 金额：**¥56,000,000**（**占公司当年营业利润 75%**）
- 对方：境外母公司（实际税负 < 5%）

### 凭证材料（**不齐全**）

| 编号 | 类型 | 问题 |
|---|---|---|
| E01 | 服务合同（**无定价依据**） | ❌ |
| E02 | 母公司"提供服务"的实质性证明 | ❌ |
| E03 | 关联业务往来报告表 | ❌ 缺失 |
| E04 | 本地文档（同期资料） | ❌ 缺失 |

### 自动识别要素

| ID | 触发 | 风险等级 |
|---|---|---|
| A-LAW-001 | 关联方利息支出**债权性 5:1 权益性**超标 | warning |
| A-LAW-003 | 关联交易未独立交易原则报告 | **violation** |
| R-LAW-006 | 关联交易定价显著偏离独立交易原则 | **violation**（特别纳税调整） |
| P-LAW-005 | 关联业务往来报告表未提交（60 日内） | **violation** |

### 法规点
- 所得税法第 42 条（独立交易原则）
- 所得税法第 44 条（关联申报）
- 所得税法第 46 条（资本弱化）
- 国税发 2009-2 号（关联交易资料）

### 决策流程

```
命中独立交易原则违反
   ↓
触发特别纳税调整风险
   ↓
needs_hitl=True
   ↓
升级到 CFO + 总经理 + 外部税务师
   ↓
立即建议：补充关联申报 + 同期资料 + 接受特别纳税调整 + 加收利息（LPR+5bp）
```

## 总体测试策略

### 单元测试套件

```python
# services/agent/tests/test_fiscal_violation_scenarios.py

import pytest
from agent.audit_expert import submit_audit_task

VIOLATION_SCENARIOS = [
    # (scenario_id, expected_status, expected_max_score, critical_expected, dual_expected)
    ("V1", "blocked", 20, True, True),
    ("V2", "blocked", 20, True, False),
    ("V3", "blocked_then_resubmit", 60, False, False),
    ("V4", "blocked_and_adjust", 30, False, False),
    ("V5", "blocked_then_adjust", 40, False, False),
]


@pytest.mark.parametrize(
    "scenario_id,expected_status,max_score,critical_expected,dual_expected", VIOLATION_SCENARIOS
)
def test_violation_scenario(
    scenario_id, expected_status, max_score, critical_expected, dual_expected
):
    """验证明显违规场景被拦截"""
    task = load_fixture(f"fiscal-tax/test-scenarios/违规业务-高风险审核.md#{scenario_id}")
    result = submit_audit_task(task)

    assert result["status"] in ["blocked", "blocked_then_resubmit", "blocked_and_adjust"]
    assert result["score"] < max_score
    assert result["needs_hitl"] is True
    assert len(result["compliance_violations"]) > 0

    if critical_expected:
        assert any(v["severity"] == "critical" for v in result["compliance_violations"])
    if dual_expected:
        assert result.get("dual_required") is True

    # 必须有 SHA-256 签名链审计
    assert result["audit_log"]["sha256_evidence_hash"] is not None
```

### 拒绝率基准

| 风险等级 | 拒绝率 | 走人工率 |
|---|---|---|
| **critical** | 100% | 100% |
| **violation** | 100% | 90%+ |
| **warning** | 0% | 30% |

### 时延基准

| 场景 | 期望时延 (P95) |
|---|---|
| V1（critical + dual） | < 5s |
| V2（critical + 多级审批） | < 6s |
| V3（violation + 重提交） | < 3s |
| V4（special adjustment） | < 4s |
| V5（input reversal） | < 2s |

---

**核心结论**：EAIDE 审核专家系统的**拦截能力**应当对 **V1-V5** 五个场景全部通过测试——这套 fixture 应当在 CI 上**强制跑一遍**，任何一项失败都视为**严重系统缺陷**。
